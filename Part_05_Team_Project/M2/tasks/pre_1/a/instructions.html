17.3. Milestone 2 - Operating the Greenhouse (Individual)#

At a Glance

What you will do: Operate the greenhouse simulator by hand. Use sliders and simple rules to keep five lettuce plants alive on Mars.

What you will submit: Short written answers in Gradescope.

Before you write software to control the greenhouse, you will operate it yourself. The interactive sandbox runs the same physics, sensors, and faults as the acceptance test. In this activity, you are the controller.

The greenhouse is one coupled system. A change you make to control one variable also moves the others. In this activity you see this coupling for the first time.

17.3.1. Setup#

The sandbox is a desktop application you download and run on your own laptop. Download the sandbox kit, greenhouse_sandbox.zip, and extract it into your ENGR 131 course folder, not your Downloads folder. The extracted greenhouse_sandbox folder contains run_sandbox.py, the martian_greenhouse_sim/ package, a controller template, the practice acceptance check, and a QUICKSTART.md.

How to Extract the Zip File

The sandbox cannot launch from inside a zip file, so extract the files into a regular folder first. Use your ENGR 131 course folder, the folder where you keep all of your course documents. Files left in the Downloads folder are easy to lose or delete by accident, and later milestones reuse the sandbox folder.

On Windows:

  1. In File Explorer, move greenhouse_sandbox.zip from your Downloads folder into your ENGR 131 course folder.

  2. Right-click the zip file and select Extract All.

  3. Keep the suggested destination, which ends in greenhouse_sandbox, and select Extract.

Double-clicking a zip file in File Explorer opens a view of its contents that looks like an ordinary folder. Those files are not extracted, and the sandbox does not launch from that view.

On macOS:

  1. In Finder, move greenhouse_sandbox.zip from your Downloads folder into your ENGR 131 course folder.

  2. Double-click the zip file. macOS creates a greenhouse_sandbox folder next to it.

Some browsers extract zip files automatically after downloading. If a greenhouse_sandbox folder already appears in your Downloads folder, move that folder into your ENGR 131 course folder instead of extracting the zip file again.

When you finish, your ENGR 131 course folder contains a greenhouse_sandbox folder with run_sandbox.py directly inside it. You can delete the zip file.

Launch the sandbox from inside the greenhouse_sandbox folder.

python run_sandbox.py

The sandbox opens a window with the greenhouse visual, live sensor readings, a rolling chart, and a tabbed panel of actuator sliders, rule tables, and fault buttons.

The sandbox requires Python 3.9 or newer with tkinter and matplotlib. The python.org installer includes tkinter on Windows and macOS. On Linux, run sudo apt install python3-tk. Install matplotlib with pip install matplotlib. You do not need numpy, pandas, or any Gradescope packages. The QUICKSTART.md inside the zip has the full details.

Note

The sandbox needs a local Python installation with a display. It does not run in Codespaces. Install instructions are in the course software guide. If you cannot run it locally, complete the Fallback Exercise at the bottom of this page instead. The fallback uses the same telemetry log your team analyzes in the team task.

17.3.2. Greenhouse Operation Plan#

Work through these steps in order. Take notes as you go, because the Gradescope questions ask about what you observed.

  1. Run with no control. Press Play with all actuators at zero. Watch the temperature trace and the plants. How long do the plants last, and what kills them?

  2. Operate by hand. Press Reset. Using only the sliders, try to hold the temperature near the setpoints through one full sol. Watch how much heater power you need when night falls and the outside temperature drops toward -70 °C.

  3. Control with rules. Switch to Auto and open the Rules tab. Build if/then rules for the heater. They work like the if/elif logic from the Python logic module. Do your rules perform better than manual operation?

  4. Freeze a sensor. From the Faults tab, freeze the K30 CO2 sensor. Watch both CO2 readouts. What would a controller that reads only the K30 do right now?

  5. Run a dust storm. Trigger the dust storm. What happens to light and temperature? What does it cost your rules to keep the plants alive through it?

  6. Run three sols on rules. Using rules alone, keep the plants alive and healthy for three sols as best you can. Note where your threshold rules start to fail: for example, oscillation, overshoot, or conditions the rules do not anticipate.

17.3.3. Reflection#

Navigate to 17.1.2 Milestone 2 - Operating the Greenhouse (Individual) on gradescope and answer the following questions.

Recommendation

class: warning : We recommend writing answers to questions in a Word document, saving it locally to your computer, and then copy-paste your answers into Gradescope. This will help you keep a local record of your work.

  1. With no control at all, what failed first, and roughly how long did the crop survive?

  2. Describe one behavior of the system that surprised you when operating by hand, and the physics reason for it.

  3. When the K30 froze, how did you know it was frozen? What information would a controller need to detect the same thing?

  4. Where did your threshold rules perform worst? Describe the behavior (for example, oscillation around the setpoint, slow recovery after the storm, or humidity stuck out of range).

  5. Give one concrete example of coupling you saw: a change you made for one variable that forced a change in another (for example, running the heater dried the air, turning up the LEDs also warmed the air, or watering the soil raised the humidity).

  6. After this session, which single variable do you expect to be hardest for software to control, and why?

17.3.5. Fallback Exercise (only if you cannot run the sandbox)#

Open your team’s GHU-1 telemetry log (linked from the team task). In Excel, plot t_in_c against sol as a line chart for sols 0 to 1. Answer questions 1, 2, and 6 above from the log instead of the sandbox. For Q1, GHU-1’s actuator columns all read 0 % for the final stretch of the log. Treat that stretch as “no control at all”.
