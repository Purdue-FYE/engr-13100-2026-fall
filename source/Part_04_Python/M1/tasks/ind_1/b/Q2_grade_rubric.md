# Grading Rubric for Q2 in Python 1, Ind_1/b

### Written Report Grading Rubric
#### Medical Device Prototype Test Simulation Memo
#### Total: XX Points
________________________________________
### 1. Professional Format & Tone (XX Points)

#### Evaluates memo structure, audience awareness, and professionalism

| Level	| Criteria |
|:---|:---|
| Exceeds Expectations | Uses proper memo format (To, From, Subject, Date). Writing is formal clear, and appropriate for a technical supervisor. No casual language or first-person reflections. |
| Meets Expectations | Memo format is mostly correct. Tone is professional with minor lapses in wording or structure. |
| Needs Improvement	| Missing memo elements or uses informal, conversational, or student-focused language. |
________________________________________
### 2. Purpose & Program Description (XX Points)

#### Evaluates clarity of what the program does and why

| Level	| Criteria |
|:---|:---|
| Exceeds Expectations | Clearly explains the purpose of the simulation and connects it to prototype testing or engineering evaluation. Describes what data is generated and its relevance. |
| Meets Expectations | States the program’s purpose and generally describes what it does. Limited connection to real-world testing context. |
| Needs Improvement	| Purpose is unclear, vague, or inaccurate. Little explanation of program function. |
________________________________________
### 3. Technical Accuracy & Detail (XX Points)

#### Evaluates understanding of data handling and analysis

| Level	| Criteria |
|:---|:---|
| Exceeds Expectations | Correctly references lists, averaging, thresholds, comparisons, and/or mathematical operations. Uses technical terms accurately and specifically. |
| Meets Expectations | Describes calculations and analysis correctly but in general terms. Limited use of technical vocabulary. |
| Needs Improvement	| Contains incorrect descriptions of how the program processes or evaluates data. |
________________________________________
### 4. Pass/Fail Logic Explanation (XX Points)

#### Evaluates clarity of decision-making process

| Level	| Criteria |
|:---|:---|
| Exceeds Expectations | Clearly explains how the performance threshold is applied and how the final PASS/FAIL status is determined using program logic. |
| Meets Expectations |	Mentions that a threshold is used and that a pass/fail decision is made, but explanation lacks detail. |
| Needs Improvement	| Pass/fail criteria are unclear or missing. |
________________________________________
### 5. Debugging & Error Awareness (XX Points)

#### Evaluates understanding of programming errors

| Level	| Criteria |
|:---|:---|
| Exceeds Expectations | Identifies a specific error type (TypeError, ValueError, NameError, or IndexError), explains its cause, and clearly describes how it was resolved. |
| Meets Expectations | Names an error and provides a basic explanation of what went wrong or how it was fixed. |
| Needs Improvement	| Error discussion is missing, incorrect, or lacks meaningful explanation. |
________________________________________
### 6. Clarity, Organization & Writing Quality (XX Points)

#### Evaluates readability and structure

| Level	| Criteria |
|:---|:---|
| Exceeds Expectations | Well-organized paragraphs, smooth transitions, clear and concise sentences. No major grammar or spelling errors. |
| Meets Expectations | Generally clear and readable. Minor grammar or structure issues that do not impact understanding. |
| Needs Improvement	| Disorganized, difficult to follow, or frequent grammar and spelling errors. |
________________________________________
### Quick Scoring Guide for TAs

| Performance Level	| Typical Score Range |
|:---|:---|
| A / Exceeds Expectations	| 90–100% of points |
| B / Meets Expectations | 75–89% of points |
| C or Below / Needs Improvement | Below 75% of points |
________________________________________
### Optional TA Comments Bank

#### You can give graders a few reusable phrases for consistency:

- Strong:

    “Clear explanation of how the threshold and comparison logic determine device status. Good use of technical language.”

- Satisfactory:

    “Program purpose is explained, but more detail on how data is analyzed would strengthen this report.”

- Needs Improvement:

    “Pass/fail criteria are unclear. Please explain how the program decides whether the device meets performance standards.”
